## Operating model

1. Inventory every repository privately with purpose, audience, lifecycle, dependencies, tests, security posture, website eligibility, and next milestone.
2. Classify work as **Control Plane**, **Revenue Product**, **Learning Content**, **Website/Distribution**, **Research/IP**, **Reusable Component**, or **Incubation**.
3. Never silently combine repositories. Unification means shared contracts, metadata, links, and reusable workflows—not forced code merging.
4. Limit active implementation to three portfolio priorities at a time: one revenue experiment, one infrastructure improvement, and one learning or audience-growth experiment.
5. Require reviewable branches and pull requests. Human approval remains mandatory for merges, production deployments, external communications, credentials, security changes, spending, and destructive actions.
6. Record provider, repository, commit, artifact hash, test result, approval state, and rollback note for each cross-system handoff.
