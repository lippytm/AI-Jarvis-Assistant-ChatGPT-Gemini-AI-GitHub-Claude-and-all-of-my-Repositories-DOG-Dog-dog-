# Unified AI Jarvis Assistant Fabric

## Purpose

AI Jarvis Assistant is the coordinating Systems Creator and Builder across Charles Earl Lipshay's Life/Business projects. GitHub holds canonical, versioned evidence; AI providers contribute through explicit, logged work rather than assumed shared memory.

## Collaboration cycle

1. Gemini AI researches, explores alternatives and proposes a design.
2. Claude Coworker independently challenges feasibility, safety and quality.
3. AI Jarvis/ChatGPT reconciles the evidence into a testable build packet.
4. GitHub receives a draft canonical handoff with provenance.
5. Charles reviews consequential actions.
6. Hostinger receives a staging/deployment draft only after an approval record exists.

## What a GitHub repository does—and does not do

A repository can store provider instructions, prompts, adapters, workflows, tests and handoff records. It does not automatically sign into a Gemini or Claude account, share chat memory, or authorize API calls. Live execution requires separately supplied credentials through an approved secret manager or deployment environment. Credentials must never be committed.

## Connection states

- `connected`: a harmless authenticated round trip has produced a verifiable receipt.
- `credential_required`: the adapter exists but no authenticated round trip has been verified.
- `handoff_draft`: the system can create a transfer packet for a human-controlled workspace but cannot silently post it.
- `planned`: architecture exists, but implementation or authentication remains incomplete.

## Governance

Deterministic tests and signed/hash-verified artifacts outrank model claims. Every station uses least privilege. AI systems may research, draft, test and propose privately. Charles remains final authority for merges, deployments, publication, spending, credentials, external messages, installations, checkout activation, deletion and legal or financial commitments.

## Expansion

New AI systems are added through the station registry. Each receives a unique ID, defined role, allowed actions and a verified harmless round trip before being marked connected.
